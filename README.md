## 第一次設定
1. Supabase → SQL Editor → New query
2. 執行 `supabase-setup.sql`
3. Authentication → Users 建立四人的 Email / Password 帳號
4. 建議四個帳號建立完成後關閉公開 Sign Up
5. GitHub Pages 更新 `index.html`、`styles.css`、`Jeju-banner.png`
6. 四人登入同一網址，即可共同編輯

## 即時同步
共同資料使用 `shared_items` + Supabase Realtime。
其他人新增、修改、刪除後，開著 App 的成員會自動重新讀取。

## v16g：自動估算行程卡之間的開車距離與時間
- 每兩張相鄰行程卡之間固定使用「🚗 開車」。
- App 會使用行程卡的地址自動取得座標，再估算道路距離與行車時間。
- 距離顯示 km，時間顯示分鐘。
- 新增、修改、刪除或拖曳排序行程後會重新估算相關路段。
- 每段右側有 ↻ 可以手動重新估算。
- 估算結果仍可直接手動修改 km / 分鐘，且會同步到 Supabase。
- 目前估算來源為 OpenStreetMap Nominatim + OSRM 公開路線服務，不是 NAVER 即時交通，因此實際開車時間可能因塞車、施工或地圖資料差異而不同。


## v16h：Kakao Mobility 真實開車路線
- 行程卡之間的自動距離 / 時間改由 Cloud Run 代理呼叫 Kakao Mobility Directions API。
- 前端只保存 Cloud Run 公開服務網址，不會把 Kakao REST API Key 放進 GitHub Pages。
- 地址仍先由目前的地理編碼流程轉成座標，再以 `經度,緯度` 傳給 Cloud Run。
- Cloud Run 服務：
  `https://jeju-routes-api-913779091484.asia-northeast3.run.app`
- 回傳結果會自動寫入 `travelKm` 與 `travelMinutes`，並同步到 Supabase。
- 新增、修改、刪除、拖曳排序行程後仍會自動重新估算；右側 ↻ 可強制重新估算。
- PWA / Service Worker 快取版本同步更新為 `v16h`。

## v16j：Kakao 地址定位
- 前端不再使用 Nominatim / OpenStreetMap 做地址轉座標。
- 地址 / 店名會先送到既有 Cloud Run，再由 Kakao Local API 查座標。
- Cloud Run 先用 Kakao 地址搜尋；找不到時會再用 Kakao 關鍵字搜尋。
- Kakao REST API Key 仍只留在 Cloud Run。
- 路線流程：行程地址 / 店名 → Kakao Local → Kakao Mobility → 距離 / 分鐘。
- Cloud Run 需同步更新 `cloud-run-index.js`，網站 v16j 才能使用新定位流程。
